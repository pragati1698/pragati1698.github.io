Case study 01 / Agent infrastructure

An LLM can discover. A system should control execution.

A browser agent is useful only if its actions are bounded, reproducible, and recoverable. I built Agent Hands to explore that separation in a constrained, inspectable environment.

The problem

LLMs can interpret unfamiliar workflows, but letting the model improvise on every execution creates uncertainty. A model may propose an unsafe action, repeat a side effect, or keep going when the interface no longer matches expectations.

For a portfolio-scale demonstration, I wanted to preserve the flexibility of model discovery without making the model the authority over execution.

Models can propose actions. The runtime decides what is allowed.

The architecture

The system uses a fictional legacy-style banking interface and a deliberately constrained set of supported browser actions. The browser, policy, model discovery, replay engine, verification, and human handoff are separate implementation concerns.

01

A live LLM navigates observed UI state one validated, structured decision at a time.

02

Only a verified sequence becomes a typed, parameterized capability artifact.

03
Authorize

A Python code-owned policy restricts destinations and approved browser operations.

04

A separate engine follows recorded steps without invoking an LLM.

The system checks expected state; when uncertain, it pauses for operator intervention.

Key decisions

Policy is independent of the model

The policy lives in Python code. Neither a generated model response nor a saved workflow artifact can grant more authority to itself. The demo permits a local origin and a narrow set of read-only operations.

Semantic targeting, not guessing

Actions use explicit labels and accessible role/name targeting. Ambiguous targets fail rather than silently falling back to an arbitrary element.

Verification before continuing

Every replay step checks the next expected state, and a stopped workflow is not blindly retried when an action may have partially applied.

Human control is a first-class state

In the demonstrated handoff path, the operator takes over the same browser session and automation resumes only after verifying the expected checkpoint.

What the demonstration shows

The repository includes a live model discovery trace, a replay with a different fictional member, a member-not-found outcome, a successful human takeover and resume, and a separate handoff timeout case.

The live capability has three recorded semantic steps. Replaying that artifact does not import or call the model client. Automated tests cover policy rejection, validation, browser behavior, and handoff using simulated operator tests. Sanitized evidence is linked from the repository.

What this is — and isn't

This is a scoped demonstration with fictional data, a constrained browser app, and a local human-operator path. It is not a hardened operating-system sandbox, comprehensive authorization service, or production-ready agent security platform.

Next research areas include stronger agent identity, external policy engines, sandboxing, adversarial evaluations, durable approvals and metrics for unsafe actions versus false blocks.
